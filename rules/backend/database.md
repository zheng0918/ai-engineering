# database — 数据库与 SQL 规范

> 本文件规定数据库建表、迁移脚本与 DDL 编写规范。

---

## 1. 数据库选型

- **默认 PostgreSQL 16**（项目以实际为准）
- MyBatis-Plus 作为唯一 ORM
- 方言通过 `PaginationInnerInterceptor(DbType.POSTGRE_SQL)` 配置

---

## 2. 建表规范

### 2.1 命名约定

| 对象 | 命名规范 | 示例 |
|---|---|---|
| 表名 | `{prefix}_{name}` 或 `{name}s`（蛇形） | `t_user` / `users` |
| 主键 | `id BIGSERIAL` / `id BIGINT AUTO_INCREMENT` | — |
| 普通列 | 蛇形命名 | `user_name`、`created_at` |
| 索引 | `idx_{table}_{column}` | `idx_users_username` |
| 唯一约束 | `uk_{table}_{column}` | `uk_users_username` |

### 2.2 必须的审计列

每张业务表必须包含：

```sql
tenant_id   BIGINT NOT NULL DEFAULT 0,              -- 租户 ID，预留多租户
created_by  BIGINT,                                  -- 创建人
updated_by  BIGINT,                                  -- 更新人
deleted_at  TIMESTAMP,                               -- 逻辑删除时间戳（NULL=未删）
created_at  TIMESTAMP NOT NULL DEFAULT now(),        -- 创建时间
updated_at  TIMESTAMP NOT NULL DEFAULT now()         -- 更新时间
```

### 2.3 完整建表示例

```sql
CREATE TABLE IF NOT EXISTS users (
    id            BIGSERIAL PRIMARY KEY,
    username      VARCHAR(64) UNIQUE NOT NULL,
    password_hash VARCHAR(128) NOT NULL,
    real_name     VARCHAR(64),
    role          VARCHAR(16) NOT NULL DEFAULT 'editor',
    status        VARCHAR(16) NOT NULL DEFAULT 'ACTIVE',
    tenant_id     BIGINT NOT NULL DEFAULT 0,
    metadata      JSONB NOT NULL DEFAULT '{}',
    created_by    BIGINT,
    updated_by    BIGINT,
    deleted_at    TIMESTAMP,
    created_at    TIMESTAMP NOT NULL DEFAULT now(),
    updated_at    TIMESTAMP NOT NULL DEFAULT now()
);

-- 表和列注释（必须）
COMMENT ON TABLE  users IS '应用用户。承载账号密码登录与 RBAC 角色。';
COMMENT ON COLUMN users.username IS '登录用户名，全局唯一。';
COMMENT ON COLUMN users.password_hash IS 'BCrypt 密码哈希；绝不能在响应体或日志输出。';
COMMENT ON COLUMN users.role IS '系统角色：admin/editor/viewer。';
COMMENT ON COLUMN users.status IS '账号状态：ACTIVE 正常 / DISABLED 停用。';
COMMENT ON COLUMN users.deleted_at IS '逻辑删除时间戳；NULL 表示未删除。';
```

## 3. 迁移文件规范

### 3.1 文件命名

使用 Flyway 命名约定：
```
V{version}__{description}.sql
例如：V1__init_schema.sql、V2__add_user_status.sql
```

### 3.2 文件头注释（必须）

每个迁移文件**头部必须**用 `-- ` 注释块说明：

```sql
-- 目的：建用户表与知识库表，首次初始化。
-- 破坏性：否（仅 CREATE IF NOT EXISTS，幂等可重跑）。
-- 依赖：无（首个迁移）。
-- 幂等：是（IF NOT EXISTS + WHERE NOT EXISTS）。
```

### 3.3 已有迁移不可修改

**禁止修改已经在生产或 dev 库执行过的 V*.sql 内容**。如需修订表结构，**新增 V{n+1}__xxx.sql**。

## 4. 索引规范

```sql
-- 条件索引（仅未删除的行）
CREATE INDEX IF NOT EXISTS idx_documents_kb_id ON documents(kb_id) WHERE deleted_at IS NULL;

-- 复合索引
CREATE INDEX IF NOT EXISTS idx_tasks_owner_status ON tasks(owner_id, status) WHERE deleted_at IS NULL;

-- 唯一约束
UNIQUE (kb_id, user_id)
```

## 5. 初始化数据

### 5.1 BCrypt 密码哈希生成（强制）

**`password_hash` 字段的值必须通过 Java 代码生成，严禁手动编造或从外部复制。**

迁移脚本中写初始密码时，先运行以下代码获取真实哈希：

```java
import org.springframework.security.crypto.bcrypt.BCryptPasswordEncoder;

// 运行前确保已引入 spring-security-crypto 依赖
String hash = new BCryptPasswordEncoder().encode("admin123");
System.out.println(hash);  // 将输出结果复制到迁移脚本
```

> **为什么不能手动编造**：BCrypt 哈希包含盐值、版本标识、加密轮数和密文，格式为 `$2a$10$<22字符salt><31字符hash>`。任一字节错误都会导致 `matches()` 返回 false，且从日志/输出来看哈希"格式正确"，极具迷惑性。

### 5.2 示例

```sql
-- 初始管理员（密码 admin123 的 BCrypt 哈希，必须用 BCryptPasswordEncoder.encode() 生成）
-- 仅 dev/POC 使用，生产环境必须修改密码
INSERT INTO users (username, password_hash, real_name, role, status)
SELECT 'admin', '$2a$10$O6OpSAWFg9Kp/HLTceL97e/qcWNgatJcMxPpfZxD3VhS3JUvNrqAm', '系统管理员', 'admin', 'ACTIVE'
WHERE NOT EXISTS (SELECT 1 FROM users WHERE username = 'admin');
```

> **注意**：上面示例中的哈希值仅对该示例的明文 "admin123" 有效，实际使用时必须用自己的明文重新生成。

## 6. COMMENT ON 规范（必须）

- **每张业务表必须有 `COMMENT ON TABLE`**：用途 + 隔离规则 + 关键约束
- **每个业务字段必须有 `COMMENT ON COLUMN`**：业务含义 + 取值范围 + 与外键关系
- 新建表的迁移文件必须同时写 `CREATE TABLE` 和对应 `COMMENT ON`
- 既有表追加字段时，同迁移文件追加 `COMMENT ON COLUMN`

## 7. SQL 方言约束（PostgreSQL）

项目使用 PostgreSQL，**严禁使用任何 MySQL 专有语法或函数**。编写 SQL 时必须确保对 PostgreSQL 兼容。

### 7.1 常见 MySQL 专有语法 → PostgreSQL 等价写法

| MySQL（禁止） | PostgreSQL（正确） |
|---|---|
| `GROUP_CONCAT(col ORDER BY x SEPARATOR ' > ')` | `STRING_AGG(col, ' > ' ORDER BY x)` |
| `` `table_name` `` / `` `column` ``（反引号） | `"table_name"` / `"column"`（双引号，非必须时不加） |
| `LIMIT offset, count` | `LIMIT count OFFSET offset` |
| `REPLACE INTO` | `INSERT ... ON CONFLICT ... DO UPDATE` |
| `INSERT IGNORE` | `INSERT ... ON CONFLICT DO NOTHING` |
| `ON DUPLICATE KEY UPDATE` | `ON CONFLICT ... DO UPDATE` |
| `AUTO_INCREMENT` | `BIGSERIAL` / `GENERATED BY DEFAULT AS IDENTITY` |
| `NOW()` | `now()`（PostgreSQL 也支持，但推荐 `now()`） |
| `IFNULL(a, b)` | `COALESCE(a, b)` |
| `IF(cond, a, b)` | `CASE WHEN cond THEN a ELSE b END` |
| `STR_TO_DATE(str, fmt)` | `TO_TIMESTAMP(str, fmt)` |
| `DATE_FORMAT(d, fmt)` | `TO_CHAR(d, fmt)` |
| `YEAR(col)` / `MONTH(col)` | `EXTRACT(YEAR FROM col)` / `EXTRACT(MONTH FROM col)` |
| `UUID()` | `gen_random_uuid()` |
| `TINYINT` | `SMALLINT` 或 `BOOLEAN` |
| `DATETIME` | `TIMESTAMP` |
| `LONGTEXT` / `MEDIUMTEXT` | `TEXT` |
| `ENGINE=InnoDB` | 不存在，删除 |

### 7.2 互兼容函数（可安全使用）

以下函数在 MySQL 和 PostgreSQL 中行为一致，可直接使用：
`CONCAT`、`LENGTH`、`UPPER`、`LOWER`、`TRIM`、`SUBSTRING`、`REPLACE`、`COALESCE`、`NULLIF`、`COUNT`、`SUM`、`AVG`、`MAX`、`MIN`、`ROUND`、`ABS`

### 7.3 模糊查询注意

```sql
-- 正确：PostgreSQL 中 CONCAT 可用，但更推荐 || 运算符
WHERE name LIKE CONCAT('%', #{keyword}, '%')
-- 等价写法（更地道）：
WHERE name LIKE '%' || #{keyword} || '%'
```

## 8. 禁止事项

- ❌ 建表缺少 `COMMENT ON TABLE` / `COMMENT ON COLUMN`
- ❌ 没有审计列
- ❌ 修改已应用过的 V*.sql 文件
- ❌ 迁移文件缺少头部注释
- ❌ 表名/列名用驼峰（必须蛇形）
- ❌ 无索引的大表查询
- ❌ 使用 MySQL 专有语法/函数（`GROUP_CONCAT`、反引号、`LIMIT x,y`、`REPLACE INTO` 等）
